Transações bancárias
com pilha e fila em C

Uma demonstração no terminal onde clientes depositam, sacam, transferem, pagam (na hora ou agendado) e estornam. Cada estrutura de dados resolve um problema real do banco.

O problema

Um banco precisa responder a três perguntas

Quem é atendido primeiro?

Pedidos chegam o tempo todo. A ordem precisa ser justa, e ela decide quem fica sem saldo quando dois pedidos disputam o mesmo dinheiro.

Como desfazer um erro?

O estorno precisa desfazer a última operação efetivada sem deixar os saldos inconsistentes.

E as contas do mês?

Pagamentos agendados executam na data certa, na ordem certa, mesmo quando caem no mesmo dia.

Base de tudo

Uma struct é uma ficha com vários campos

Cada pedido vira uma Operacao. A mesma ficha passa pela fila, pela pilha, pela agenda e pelo histórico.

Regra única para movimentar dinheiro: sai da origem e entra no destino. Depósito não tem origem e saque não tem destino.

typedef struct {
    int    numero;       /* ordem de chegada  */
    int    tipo;         /* TIPO_SAQUE...     */
    int    contaOrigem;  /* de onde sai       */
    int    contaDestino; /* para onde vai     */
    double valor;
    int    data;         /* AAAAMMDD (agenda) */
} Operacao;

Fila · FIFO

Quem pediu primeiro é atendido primeiro

Carla tem R$ 50 e pede dois saques. O primeiro da fila leva o dinheiro e o segundo é recusado. Se a ordem fosse outra, o resultado seria outro. Por isso a fila não é decorativa.

#1 saque 40 ✓
#2 saque 30 ✗ saldo
#3 transf. 150 ✓
/* vetor circular: o fim "dá a volta" */
fim = (f->inicio + f->quantidade)
      % CAPACIDADE_FILA;
f->itens[fim] = op;
f->quantidade++;

/* desenfileirar: sai o do início */
*saida = f->itens[f->inicio];
f->inicio = (f->inicio + 1) % CAPACIDADE_FILA;
f->quantidade--;

Pilha · LIFO

O estorno desfaz a última efetivada

Cada operação efetivada vai para o topo. Desfazer na ordem inversa sempre leva a um estado que já existiu, então os saldos ficam consistentes.

TOPO → #3 transferência 150
#1 saque 40

Pilha vazia → "Nada a estornar."

int desempilhar(Pilha *p, Operacao *saida)
{
    if (pilhaVazia(p)) {
        return 0;  /* nada a estornar */
    }
    p->quantidade--;
    *saida = p->itens[p->quantidade];
    return 1;
}

Conceito novo

Por que Pilha *p?

Sem ponteiro, a função recebe uma cópia da pilha, e o empilhamento se perde quando a função termina. Com o ponteiro, ela recebe o endereço e altera a pilha verdadeira.

O mesmo truque serve para "devolver" a operação desempilhada pelo parâmetro saida.

Pilha efetivadas;
Operacao desfeita;

iniciarPilha(&efetivadas);   /* & = endereço */

if (desempilhar(&efetivadas, &desfeita)) {
    imprimirOperacao(desfeita);
} else {
    printf("Nada a estornar.\n");
}

Agenda · qsort

qsort não é estável, então desempatamos

Com datas iguais, o qsort pode trocar dois pagamentos de lugar. O número de entrada é o segundo critério, o que mantém a ordem de chegada (FIFO) no mesmo dia.

Agendado comoExecuta em
#4 · 10/11 · R$ 100#5 · 08/11
#5 · 08/11 · R$ 50#4 · 10/11
#6 · 10/11 · R$ 30#6 · 10/11 (empate: #4 entrou antes)
int compararAgendados(const void *a,
                      const void *b)
{
    const Operacao *x = a, *y = b;

    /* 1º: data mais cedo vem antes */
    if (x->data < y->data) return -1;
    if (x->data > y->data) return  1;

    /* 2º: empate -> quem entrou antes */
    if (x->numero < y->numero) return -1;
    if (x->numero > y->numero) return  1;
    return 0;
}

Histórico · lista encadeada

Cresce sem limite, nó por nó

Cada evento (efetivada, recusada, estornada, agendada, cancelada, paga) vira um nó criado com malloc. Guardamos o último nó para inserir no fim sem percorrer a lista. Ao sair, free devolve toda a memória.

Processo

Como usamos IA no projeto

  • As decisões de estrutura (fila, pilha, qsort com desempate, lista) foram da equipe. A IA implementou em incrementos pequenos.
  • Cada iteração está no processo-ia.md: pedido, solução, alteração, motivo e resultado.
  • Uma segunda IA (Codex) revisou o código e achou um bug real: digitar a conta 0 como origem de uma transferência criava dinheiro. Ele foi corrigido e ganhou teste.
