O problema

Um banco precisa responder a três perguntas

Quem é atendido primeiro?

Pedidos chegam o tempo todo. A ordem precisa ser justa, e ela decide quem fica sem saldo quando dois pedidos disputam o mesmo dinheiro.

Como desfazer um erro?

O estorno precisa desfazer a última operação efetivada sem deixar os saldos inconsistentes.

E as contas do mês?

Pagamentos agendados executam na data certa, na ordem certa, mesmo quando caem no mesmo dia.

Base de tudo

Uma struct é uma ficha com vários campos

Cada pedido vira uma Operacao. A mesma ficha passa pela fila, pela pilha, pela agenda e pelo histórico.

Regra única para movimentar dinheiro: sai da origem e entra no destino. Depósito não tem origem e saque não tem destino.

typedef struct {
    int    numero;       /* ordem de chegada  */
    int    tipo;         /* TIPO_SAQUE...     */
    int    contaOrigem;  /* de onde sai       */
    int    contaDestino; /* para onde vai     */
    double valor;
    int    data;         /* AAAAMMDD (agenda) */
} Operacao;

Fila · FIFO

Quem pediu primeiro é atendido primeiro

Carla tem R$ 50 e pede dois saques. O primeiro da fila leva o dinheiro e o segundo é recusado. Se a ordem fosse outra, o resultado seria outro. Por isso a fila não é decorativa.

Operacao desenfileirar(void)
{
    Operacao saida = {0}; /* numero 0 indica que não havia operação. */
    if (filaVazia()) return saida;
    saida = banco.pedidos.itens[banco.pedidos.inicio];
    banco.pedidos.inicio = (banco.pedidos.inicio + 1) % CAPACIDADE_FILA;
    banco.pedidos.quantidade--;
    return saida;
}

Pilha · LIFO

O estorno desfaz a última efetivada

Cada operação efetivada vai para o topo. Desfazer sempre a mais recente evita desmontar uma operação de que outras ainda dependem. Se o dinheiro já foi usado, o estorno é recusado e a ficha volta ao topo.

Operacao desempilhar(void)
{
    Operacao saida = {0}; /* numero 0 indica que não havia operação. */
    if (pilhaVazia()) return saida;
    banco.efetivadas.quantidade--;
    saida = banco.efetivadas.itens[banco.efetivadas.quantidade];
    return saida;
}

Como as funções trabalham

Acesso direto ao banco, retorno por valor

Existe um único banco global. As funções acessam seus campos com o ponto, como banco.efetivadas.quantidade.

Ao remover da fila ou pilha, a função devolve a operação inteira por valor. Uma operação com numero == 0 indica que a estrutura estava vazia.

Operacao desfeita;

iniciarPilha();
desfeita = desempilhar();
if (desfeita.numero != 0) {
    imprimirOperacao(desfeita);
} else {
    printf("Nada a estornar.");
}

Agenda · inserção

Ordenamos por data e número de entrada

A ordenação por inserção desloca os itens até cada pagamento chegar à posição certa. O número de entrada desempata datas iguais e mantém FIFO no mesmo dia.

int compararAgendados(Operacao x, Operacao y)
{

    if (x.data < y.data) return -1;
    if (x.data > y.data) return 1;

    if (x.numero < y.numero) return -1;
    if (x.numero > y.numero) return 1;
    return 0;
}

Histórico · vetor

Um evento em cada posição do vetor

Cada evento ocupa itens[quantidade]. Depois, o contador aumenta. O vetor guarda até 1.000 registros; se não houver espaço, o sistema recusa o comando antes de alterar o banco.

int registrarHistorico(Operacao op, int situacao, int data)
{
    int pos = banco.historico.quantidade;
    if (!historicoTemEspaco(1)) return 0;
    banco.historico.itens[pos].op = op;
    banco.historico.itens[pos].situacao = situacao;
    banco.historico.itens[pos].data = data;
    banco.historico.quantidade++;
    return 1;
}

SituaçãoResposta do sistema
Estornar sem nada efetivadoNada a estornar.
Saldo insuficientePedido recusado e registrado no histórico, sem mudar o saldo
Dois pagamentos agendados no mesmo diaExecutam na ordem de entrada (desempate pelo número)
Estornar depósito cujo dinheiro já foi gastoEstorno recusado. A operação volta ao topo e nada muda
Cancelar agendado já executado"Não há pagamento agendado com esse número"

Letras no lugar de números, data 31/02A pergunta é repetida

Qualidade

72 verificações automáticas em 4 programas de teste

teste_pilha

Pilha vazia, ordem LIFO 3, 2, 1, pilha cheia.

teste_fila

Ordem FIFO, fila cheia, vetor circular dando a volta.

teste_agendados

Datas iguais, cancelamento, só executa o que venceu.

teste_sistema

Saldo insuficiente, estorno impossível, validações e histórico cheio.

Um módulo por estrutura: pilha · fila · agendados · historico · sistema · entrada · main. Compila sem avisos com gcc -Wall -Wextra -std=c99. O simulador web usa um motor em JavaScript conferido contra a saída real do banco.exe.

Processo

Como usamos IA no projeto

  • As decisões de estrutura (fila, pilha, agenda ordenada e histórico em vetor) foram da equipe. A IA implementou em incrementos pequenos.
  • Cada iteração está no processo-ia.md: pedido, solução, alteração, motivo e resultado.
  • Uma segunda IA (Codex) revisou o código e achou um bug real: digitar a conta 0 como origem de uma transferência criava dinheiro. Ele foi corrigido e ganhou teste.
  • O código é comentado para iniciantes: struct, vetores, índices e retorno por valor são explicados ao longo do projeto.
